# گرگ | GORG — سایت رستوران

سایت رستوران گرگ، ساخته‌شده با Next.js (App Router)، TypeScript و Tailwind CSS v4.

## اجرا روی سیستم شما

```bash
npm install
npm run dev
```

سپس آدرس `http://localhost:3000` را باز کنید.

## متغیرهای محیطی

فایل `.env.example` را کپی کرده و به `.env.local` تغییر نام دهید، سپس مقادیر را کامل کنید:

- `RESEND_API_KEY` — برای ارسال ایمیل سفارش‌ها و پیام‌های تماس. اگر خالی بماند، سفارش‌ها فقط در کنسول سرور لاگ می‌شوند و سایت همچنان کار می‌کند (خطا نمی‌دهد)، اما ایمیلی ارسال نخواهد شد.
- `ORDER_RECIPIENT_EMAIL` — ایمیلی که سفارش‌ها و پیام‌ها به آن ارسال می‌شود.
- `NEXT_PUBLIC_WHATSAPP_NUMBER` — شماره واتساپ رستوران با کد کشور (بدون + و بدون صفر ابتدایی).

## ساختار

- `app/` — صفحات (خانه، منو، گالری، درباره، تماس، تسویه سفارش) و API routeها
- `components/` — کامپوننت‌های قابل‌استفاده‌ی مجدد
- `lib/menuData.ts` — منوی اولیه (۲۷ آیتم در ۶ دسته). **بار اول خودکار به دیتابیس منتقل می‌شود؛ از آن به بعد منو را از «پنل مدیریت ← منو» ویرایش کنید** (نه این فایل).
- `lib/galleryData.ts` — گالریِ اولیه. **بار اول خودکار به دیتابیس منتقل می‌شود؛ از آن به بعد گالری را از «پنل مدیریت ← گالری» ویرایش کنید** (نه این فایل).
- `lib/contact.ts` — شماره تلفن، آیدی اینستاگرام و آدرس رستوران (یک جا برای کل سایت)
- `lib/images.ts` — عکس‌های فضای رستوران و مسیر دارایی‌های برند
- `public/images/menu/` — عکس غذاها و نوشیدنی‌ها
- `context/CartContext.tsx` — منطق سبد سفارش (ذخیره در localStorage مرورگر)
- `public/images/` — لوگو و بافت قرمز برند (استخراج‌شده از تصاویر خودتان)

## نکات قبل از انتشار

1. شماره تلفن، اینستاگرام و آدرس در `lib/contact.ts` هستند؛ ساعات کاری در `components/Footer.tsx` و `app/contact/page.tsx`.
2. دامنه‌ی واقعی سایت را در `app/layout.tsx` (`metadataBase`)، `app/sitemap.ts` و `app/robots.ts` جایگزین `gorg-restaurant.ir` کنید.
3. برای عوض کردن عکس یا قیمت هر آیتم، از پنل مدیریت (بخش منو) استفاده کنید؛ عکس را همان‌جا آپلود کنید. برای عکس‌های گالری هم همین‌طور، از پنل مدیریت (بخش گالری).

## پرداخت آنلاین، ورود و نقشه‌ی آدرس

- **سفارش فقط با ورود و فقط بعد از پرداخت ثبت می‌شود.** کلید «سفارش آنلاین» تا وقتی مشتری با شماره موبایل وارد نشده مخفی است. سفارش (دیتابیس + ایمیل + پیامک) فقط بعد از تأیید زرین‌پال در `app/api/checkout/confirm/route.ts` ثبت می‌شود.
- **`ZARINPAL_MERCHANT_ID` لازم است.** اگر تنظیم نشده باشد، مشتری پیام «پرداخت آنلاین فعلاً فعال نیست» می‌بیند و هیچ سفارشی ثبت نمی‌شود. برای تست: `ZARINPAL_SANDBOX=true`.
- قیمت‌ها را سرور از منوی دیتابیس (همان که پنل ویرایش می‌کند) حساب می‌کند و شماره‌ی موبایل از نشستِ ورود می‌آید؛ مقدارِ ارسالی از مرورگر ملاک نیست.
- نام و آدرسِ هر شماره بعد از اولین سفارش ذخیره و دفعه‌ی بعد خودکار پر می‌شود. جدول‌ها و ستون‌های لازم **خودکار ساخته می‌شوند** (دیگر لازم نیست `lib/schema.sql` را دستی اجرا کنید).
- نقشه‌ی انتخاب آدرس با Leaflet و کاشی‌های OpenStreetMap است (بدون نیاز به کلید). بعد از این تغییر یک‌بار `npm install` بزنید تا `leaflet` و `qrcode` نصب شوند و `package-lock.json` به‌روز شود.

## پنل مدیریت (`/admin`)

ورود با **نام کاربری و رمز عبور** است (نه فقط رمز عبور). پنل و سایت **یک دیتابیس مشترک** دارند (تنها منبع حقیقت)؛ هر تغییر در پنل همان لحظه روی سایت اعمال می‌شود و هر سفارشِ سایت همان لحظه در پنل دیده می‌شود.

**لازم است:** `DATABASE_URL` (Neon/Postgres) و `ADMIN_PASSWORD`. جدول‌ها را سایت خودش می‌سازد (نسخه‌ی اسکیما در `lib/schema.ts`).

### ورود، حساب کاربری و بازیابی

- **اولین ورود:** چون هنوز هیچ حسابی ساخته نشده، در همان صفحه‌ی ورود یک نام کاربری دلخواه بنویسید و به‌جای رمز، همان `ADMIN_PASSWORD` را بزنید. همان لحظه حساب ساخته می‌شود و از این به بعد پنل با همین نام کاربری/رمز وارد می‌شود.
- **تغییر نام کاربری/رمز/ایمیلِ بازیابی:** از «تنظیمات ← حساب کاربری» (رمز فعلی برای تأیید لازم است).
- **رمز یا نام کاربری را فراموش کردید:** در صفحه‌ی ورود روی «نام کاربری یا رمز عبور را فراموش کرده‌اید؟» بزنید و ایمیلِ بازیابی‌ای که قبلاً در تنظیمات ثبت کرده‌اید را بدهید؛ یک لینکِ یک‌بارمصرف (تا ۳۰ دقیقه معتبر) برایتان ایمیل می‌شود تا نام کاربری/رمز جدید تعیین کنید. این ایمیل با همان سرویسِ `RESEND_API_KEY` ارسال می‌شود که برای ایمیل سفارش‌ها استفاده می‌کنید.
- **چند بار رمز اشتباه بزنید،** حساب برای مدتی موقتاً قفل می‌شود (جلوگیری از حدس‌زدن).
- **`ADMIN_PASSWORD`** بعد از اولین ورود دیگر برای کارِ روزمره لازم نیست؛ فقط به‌عنوان «رمزِ اضطراری» می‌ماند — اگر مدیرِ رستوران هم نام‌کاربری/رمز و هم ایمیلِ بازیابی را فراموش کند، با همین رمز (که فقط شما در تنظیمات هاست می‌بینید، نه کسی که پشت سیستمِ رستوران بنشیند) دوباره می‌توانید وارد شوید و برایش از نو تنظیم کنید.

| داشبورد | درآمد و سفارش امروز، سایت در برابر QR در برابر حضوری، نمودار ۷ روز، سفارش‌های در جریان، هشدار انبار، کلید باز/بسته کردن سفارش آنلاین |
| سفارش‌ها | همه‌ی سفارش‌ها با فیلتر وضعیت/منبع/تاریخ/جستجو؛ تغییر وضعیت، لغو با دلیل، چاپ فیش. **زنگ و اعلانِ سفارش جدید** (هر ۱۰ ثانیه) |

| صندوق | باز/بستن شیفت، شمارش نقد و محاسبه‌ی کسری/اضافه، ثبت هزینه‌ها |
| منو | افزودن/ویرایش/حذف آیتم و دسته، قیمت، تخفیف٪، ناموجود کردن، مخفی کردن، آپلود عکس، ترتیب |
| گالری | افزودن/حذف عکس گالری، توضیح (alt)، نمایش/مخفی کردن، جابه‌جاییِ ترتیب — همان گالری که در صفحه‌ی «گالری» سایت و تیزر صفحه‌ی اصلی دیده می‌شود |
| انبار | کالاها، ورود/خروج/ضایعات/شمارش، **دستور مصرف** (کم شدن خودکار با هر سفارش و برگشت با لغو)، گردش انبار |
| گزارش‌ها | بازه‌ی دلخواه، سایت/QR/حضوری، روش پرداخت، ساعت‌های شلوغی، فروش هر محصول، سود ناخالص/خالص، خروجی CSV برای اکسل |
| مشتریان | لیست بر اساس شماره‌ی سفارش‌ها، تکراری/وفادار |
| میز و QR | تعریف میز، ساخت و چاپ QR که به `/menu?table=کد` می‌رود؛ سفارش با شماره‌ی میز ثبت می‌شود |
| تنظیمات | باز/بسته بودن سفارش آنلاین، حداقل سفارش، هزینه‌ی ارسال، پیامک «آماده است»، وضعیت اتصال سرویس‌ها، حساب کاربری پنل |

نکته‌ها:
- سفارش‌های QR و سایت فقط بعد از پرداخت آنلاین ثبت می‌شوند؛ سفارش نقدی/کارتی از «ثبت حضوری» وارد می‌شود.
- سود فقط وقتی دقیق است که «دستور مصرف» (انبار) یا «بهای تمام‌شده» (منو) را وارد کرده باشید.
- عکس‌های آپلودشده در دیتابیس ذخیره می‌شوند (قبل از آپلود در مرورگر کوچک می‌شوند).
- سفارشِ لغوشده دیگر قابل‌بازگشت نیست؛ بازگشت وجهِ پرداخت آنلاین را باید خودتان از درگاه انجام دهید.
